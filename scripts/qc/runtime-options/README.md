# Runtime options native acceptance

Use the shared managed runner with the exact Factorio **2.1.24** development
executable and dependency lock:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/invoke-esir-dev.ps1 -Task test-plan -Suite runtime-options
powershell -ExecutionPolicy Bypass -File scripts/invoke-esir-dev.ps1 -Task qc-test -Suite runtime-options
```

The suite is an explicit extended suite, not an additional mandatory core family.
Both profiles run candidate, ordinary reload and deliberate configuration-change
cases. Checkpoint production uses the graphical backend because administration
checks require a real connected player. Keep the source, dependency selection and
fixture unchanged across the full matrix.

## Contracts covered

- Ecology defaults agree across the schema, native prototypes, runtime resolution
  and both administration pages: all switches On, Contained/Restrained/Lean.
  The native Factory Passage scanner defaults Off with budgets 256/1; a real
  circuit-selected assembler verifies parked scans, GUI observation, explicit
  refresh and enable/disable queue preservation.
- The shared ecology-administration fixture checks untouched editor refresh,
  sparse drafts, displayed-value Apply, selected-surface-only Reset and legacy
  false drafts. Saved global Off, surface Off and pending false values survive
  ordinary reload and configuration; the two profiles retain scanner On and Off.

- Native scope, type, bounds, defaults, false values and catalog completeness for
  all 113 ESIR runtime-global settings. Independent inventory of 29 conversions;
  each receives a real native edit, cache observation and restoration.
- Boolean, integer, double, enum and free-string validation; invalid mixed edits
  write nothing. Free-form unknown entity names remain permitted. Pollution
  thresholds retain the existing cross-field ordering rule.
- Native synchronous setting events, one reconciliation after a successful batch,
  nested batching, no-op edits and same-field optimistic conflicts. Distinct
  field edits from independent baseline snapshots remain compatible.
- A failure immediately after the second actual native write restores both
  values and suppresses owner reconciliation. The fault and cache probes are
  injected only into the managed private source copy; production exports and
  native userdata are not replaced.
- Native Options controls exercised by programmatic GUI callbacks: false checkbox,
  category selection retaining drafts/controls, Apply, Reload, Discard, invalid
  text, stale drafts, revoked administration rights, toolkit shutdown and native
  re-enable. A changed default alert set preserves a personal selection.
- Fresh-map behavior, controlled legacy-state import, one-shot marker and explicit
  post-import edits, persisted native values and actual module caches. Ordinary
  reload separately asserts that configuration repair did not run.
- Real pipes and tanks across generated chunks exercise ignore-list reconciliation
  with a one-slot service budget. A native destruction after a partial scan swaps
  an ignored tail behind its cursor; every ignored member must still disappear.
  Repeated edits coalesce, ignored builds are later discovered, and deletion of
  the selected surface does not block later surfaces. Unrelated segment and
  aftermath state remain owned by the original runtime table, with no rebuild.
- Ordinary reload resumes a saved native `LuaChunkIterator`; deliberate
  configuration repair separately rebuilds under the selected ignore value.
  A private checkpoint hold freezes reconciliation while the save is written,
  then releases at the first reload assertion. Query counters observe the actual
  production chunk query; no native surface methods or iterators are replaced.

## Migration profile and evidence limits

`legacy-values` constrains each hidden startup migration source to a deliberately
non-default value after runtime definitions have been constructed. The fixture
then clears only the migration marker and invokes the real migration owner. This
is **controlled legacy-state evidence**, not an authentic save created by an older
shipping version. Fresh maps must retain the new runtime defaults despite those
legacy inputs, and subsequent reload/configuration must retain explicit native
runtime selections rather than importing again.

Two independent administrator draft snapshots verify transaction conflict
semantics. They are not two connected players. Rendered layouts, mouse interaction,
two-client synchronization, audio/visual fidelity and performance require separate
evidence. The common runner disables audio. No presentation-fidelity conversion is
claimed for Singularity Lance or Anisetron in this 29-setting suite.

## Fixture maintenance

`adapter.py` uses exact staging anchors and fails when the actual owner shape
changes. It does not patch source junctions or shared package files. The shared
runner fingerprints this fixture directory. Any count change must first update
the intentional conversion/catalog contract, then the independent acceptance
inventory. Do not weaken a failed cache assertion to a second config lookup.

Registration adds only one suite adapter branch and a fixture fingerprint root;
the runner lifecycle, reporting, timeout and managed storage semantics remain
unchanged. Run the existing host conformance tests after integrating those two
small infrastructure edits. Fresh native receipts are required for acceptance.
